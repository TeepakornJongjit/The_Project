# Reading Guide — Scholarship Tracking System

> สถานะเอกสาร: Planning / Requirement / Scope Definition

## 1. จุดประสงค์ของเอกสารชุดนี้
เอกสารชุดนี้ใช้กำหนดขอบเขต ความต้องการ ผู้ใช้งาน ฟังก์ชันหลัก ข้อมูลที่เกี่ยวข้อง และการแบ่งงานสำหรับโครงงาน **ระบบติดตามทุนการศึกษา (Scholarship Tracking System)** ก่อนเริ่มพัฒนาโปรแกรมจริง

เอกสารชุดนี้เป็นการจัดโครงสร้างเอกสารเพื่อการวางแผนเท่านั้น โดยยังไม่ถือว่าเป็นการยืนยันการใช้งานจริงของระบบหรือฐานข้อมูล

## 2. ลำดับการอ่าน
1. `01_project_overview.md` — ภาพรวมโครงงานและกระบวนการหลัก
2. `02_user_stories.md` — ความต้องการในมุมมองผู้ใช้งาน
3. `03_data_and_er.md` — แนวคิดข้อมูลและความสัมพันธ์ระดับ Conceptual
4. `04_system_scope.md` — ขอบเขตสิ่งที่ระบบทำและไม่ทำ
5. `05_team_feature_allocation.md` — การแบ่งฟังก์ชันออกเป็น 6 พื้นที่งาน
6. `06_development_roadmap.md` — ลำดับระยะของโครงงาน
7. `07_foundation_and_scope.md` — กระบวนการหลักและหลักการกำหนดขอบเขต
8. `08_system_rules_and_acceptance.md` — กฎระบบและเกณฑ์ยอมรับ
9. `09_implementation_plan.md` — แผนการนำขอบเขตไปพัฒนาภายหลัง
10. `10_team_decisions.md` — ข้อตกลงและประเด็นที่ต้องตัดสินใจร่วมกัน

## 3. สิ่งที่ยังไม่อยู่ในเอกสารชุดนี้
- ภาษาโปรแกรม
- Framework
- Database technology ที่เลือกใช้จริง
- API specification
- Source code
- Deployment / Infrastructure
- การออกแบบหน้าจอเชิงละเอียด

## 4. หลักการสำคัญ
- แบ่งงานเป็น 6 โมดูลเพื่อให้สมาชิกเลือกพื้นที่รับผิดชอบได้
- ยังไม่กำหนดชื่อสมาชิกให้กับโมดูล เพื่อให้สมาชิกเลือกงานเองภายหลัง
- การแบ่งโมดูลเป็นขอบเขตงาน ไม่ได้บังคับให้ source code ต้องแยกเป็น 6 โปรเจกต์
- หากมีการเพิ่ม/ลดขอบเขต ควรบันทึกไว้ใน `10_team_decisions.md`

## 5. หมายเหตุเรื่องเอกสารอ้างอิง
โครงสร้างเอกสารได้รับแรงบันดาลใจจากรูปแบบการจัด `docs` ของ repository ตัวอย่างที่ผู้ใช้ระบุ แต่ **ไม่ได้คัดลอกเนื้อหาโดเมนของ repository ตัวอย่างมาใช้กับระบบทุนการศึกษา**
